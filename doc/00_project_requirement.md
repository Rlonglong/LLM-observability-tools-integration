## 專案主題
**LLM observability tools**

## 專題探索
* 5/7 報告，每組報告時間 25分鐘
* 組員介紹及分工、架構說明、系統展示、研究發現、心得分享

## 評分方式
* 完整性 35%
    * 對於題目及其相關內容是否有充分瞭解、研究
    * 講解是否清晰、完整，讓其他同學也能夠理解這個題目的知識
* 心得分享 30%
    * 研究後有何心得？ 有沒有改善建議？有沒有引發新想法？
* 小組分工 15%
    * 小組如何分工？使用了什麼工具協作、溝通？
* 簡報形式 20%
    * 時間掌握、表達方式、熟練程度、自信心

## 教授評分重點觀察
根據前幾組報告的現場觀察，教授特別在意以下幾點，在準備時可以對齊此方向：

1. **報告層面：** 
   報告風格不用太過艱深，類似「通識報告」即可，重點在於將這項工具的「架構」與「運作方式」拆開並講解清楚，避免全篇充滿艱澀難懂的純技術術語。
2. **Demo 細節展示 (技術層面)：** 
   Demo 可以有包裝好的 UI 介面，但**不能只跑出最終結果**。教授看起來希望帶大家看過一次「比較細節的程式實現方式」（例如：工具是如何掛載到 Agent 上的）。
3. **軟體工程規範 (分工層面 - 15%)：** 
   教授會主動追問小組使用了什麼討論工具、是否有實體會議，並極度在意「是否使用良好的軟體開發模式」。*(所以我們會導入 GitHub Projects / Kanban 流程的致勝關鍵)*
4. **真實開發體會 (心得層面 - 30%)：** 
   教授非常在意講者的「自身使用感受」。必須能回答：**「用起來跟之前的開發模式有什麼具體差異？」** 以及 **「有沒有試著套用在自己的後續開發中？」**。
5. **節錄有公信力看法：** 
   前幾組有在人報告中節錄了 AI 領域大牛或名人對於該主題的發言，或是節錄一些文章對於這些工具的看法，我有看到教授特別做筆記，推測這是教授非常喜歡的簡報呈現模式。
